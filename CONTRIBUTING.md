# Contributing

## Development workflow

1. Create a feature branch from `main`.
2. Keep each change focused on one problem.
3. Do not commit generated files, local uploads, credentials, or environment files.
4. Verify the Java backend and Python service start successfully.
5. Test affected frontend flows before opening a pull request.
6. Use clear commit messages such as `fix:`, `feat:`, `docs:`, or `chore:`.

## Pull requests

Include:
- What changed
- Why it changed
- How it was tested
- Screenshots for visible UI changes when relevant

## Security

Never commit production credentials, API keys, personal data, or real user passwords. Report security-sensitive problems privately rather than posting secrets in issues.
